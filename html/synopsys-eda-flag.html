1.2 simv 运行时 Plusargs 参数范围与含义

Plusarg合法范围 / 常用取值具体含义与使用边界
+UVM_TESTNAME=my_case（字符串）指定 UVM 测试类名，必须已在编译时用 `uvm_component_utils 注册。
+UVM_VERBOSITY=UVM_NONE | LOW | MEDIUM | HIGH | FULL | DEBUG控制 `uvm_info 打印级别。大批量扫掠用 UVM_LOW 控日志体积，定位单个 bug 时切 UVM_HIGH。
+UVM_MAX_QUIT_COUNT=正整数（默认 1）允许累计多少条 UVM_ERROR 后中止仿真；想一次看全所有错误时可设为 20。
+ntb_random_seed=正整数（如 1..20）VCS SV 随机化全局种子（影响 constraint 激励）；与误码注入种子 +pcs_ber_seed 独立。
+pcs_ber_p=0, 0.001, 0.005, 0.01, 0.0167, 0.025, 0.05, 0.1字级伯努利注入名义强度（0 为清洁信道；注意它是名义强度，如 p=0.001 实测等效 9.8e-5）。
+pcs_ber_kbits=0（整字）| 1..8（每帧 k bit）0 表示命中时整字 64 bit 翻转（主扫掠用）；1..8 表示每帧随机翻 k bit（E5 压力用）。
+buf_depth=8, 16, 32, 64, 128, 255运行时重传缓冲深度阈值 B（指针字数）；B≤128 全交付，255 用于满窗压力。
+case_frames=1000（快速）| 10000（正式）单次仿真发送帧数；决定看门狗阈值和单 run 耗时（约 3 分钟）。
+case_watchdog_ns=1.2e7（1k帧）| 8e7（10k帧）| 2e9仿真时间看门狗（单位 ns），防止死锁/丢包导致 simv 永久挂死。
+nack_log=10 | 1开启 NACK 与窗口跨度 win_span 打印，供回退窗口实验统计最大值。
+cfg_delay_ps= / +cfg_half_ps=0..348750 ps / 3125 | 3750 psCDC 跨时钟域相位偏移（45° 步进）与半周期（3125 ps=160 MHz / 3750 ps=7.5 ns 错位）。

四大高频场景的标准 Debug 排查方案（一步一步照做）

Debug 方案 1 · 仿真挂死、秒退或结果不对

步骤 1：看 run.log 行数与尾部是否有 UVM_ERROR :；若只有 1–2 行，立刻 ls -l simv 核对是不是拿了旧目录的 simv。

步骤 2：确认命令带了 +case_watchdog_ns（1000 帧 ≥ 1.2e7，10000 帧 ≥ 8e7），避免无限等。

步骤 3：把 +UVM_VERBOSITY 升到 UVM_HIGH 并用 ./simv -ucli 在出错前 50 ns 下 stop -time，show -value 看状态机与指针；或开 $fsdbDumpvars(1, top_tb) 进 Verdi 右键 Trace Driver 逆推源头。

Debug 方案 2 · PrimeTime 报黑盒位宽冲突 link 失败

症状：Width of port i_bus (32) is inconsistent with other instances (48) → Can't find design DLR_TOP。

步骤 1：确认冲突模块为 DC 未展平的参数化黑盒（本工程为 RDBUS、CLKCROSSBUS、CLKCROSSDFF 共 96 个实例）。

步骤 2：按 module...endmodule 切分 .v 网表，删除这三类实例语句。

步骤 3：把被删实例的输出端口（如 .o_bus_sample({a,b})）拆成单根标量，在对应模块 endmodule 前逐行加 assign a = 0;、assign b = 0;（严禁写 assign {a,b}=0;，PT 解析器不认），重新 link_design 即可通过。

Debug 方案 3 · DC 综合“假成功”或跑 1 小时被杀

步骤 1：绝不只看日志里的 wrote xxx.rep，必须 ls -lh + head 检查报告正文（592 B 且含 No paths. 即为 DC 假成功）。

步骤 2：如果进程中途退出，先 grep "Signal" run.log 并 df -h / /dev/shm：遇到 Received Signal 15 或根盘满，立刻迁至 /dev/shm 并确认并发 DC ≤ 2。

步骤 3：若出现 Net driven by more than one source，检查 RTL 是否在多个 always_ff 块里写了同一个数组的不同索引，改回单块写入或拆成独立数组。

Debug 方案 4 · Formality 报 unmatched 或 failing points

步骤 1：先看 report_unmatched_points——90% 来自时钟/复位端口未对齐、黑盒未声明或 SV 语法漏加 -sverilog。

步骤 2：对参数化黑盒执行 set_black_box，并确认 DC 综合时开启了 -no_seq_output_inversion（避免寄存器反相导致比较点极性不匹配）。

步骤 3：若仍有 failing，在 GUI（formality &）打开 Diagnose 对比反例向量，优先排查初始复位态与综合剪枝掉的冗余逻辑。

5. 全部常见错误码与报错信息含义速查表

覆盖本机实测踩过的所有 Synopsys 错误码与系统级异常，按报错原文直接定位含义与根治手段。

错误码 / 报错原文所属工具底层含义根治解法
UID-423
Invalid path group name		 DC K-2015.06 DC K-2015 没有内置 async_default 路径组，且报错直接写入报告文件不抛异常，造成“假成功”（报告仅 592 B 含 No paths.）。 DC 只加 enable_recovery_removal_arcs true，异步复位测量全部移交 PrimeTime 的 {**async_default**}。
UID-119
wrong type		 DC K-2015.06 set_max_fanout 传入了 net 对象，该命令只接受 port / pin / design（且打在模块输入 pin 上对内部高扇出网是 no-op）。 改用 set_app_var high_fanout_net_threshold 100000；不要打在 design 级（会触发全设计重排超 32 min 不收敛）。
UID-530
write_db unsupported		 DC K-2015.06 K-2015.06 已移除导出 .db 门级设计数据库的能力。 统一导出 .v + .sdc + .sdf 给 PrimeTime；如需 DC 内部存档用 write -format ddc。
Received Signal 15 DC / VCS 进程收到 SIGTERM 被系统或用户终止，常由根盘空间耗尽、内存超限（单 DC 6–8 GB）或超时触发。 工作目录迁入 /dev/shm（16 GB tmpfs），限制并发 DC ≤ 2，完成后及时 rm -rf /dev/shm/<dir>。
Width of port i_bus inconsistent PrimeTime / FM 综合网表中同一个未解析参数化模块（如 RDBUS）被不同位宽（32 vs 48）实例化，导致 link_design 失败并连带报 Can't find design。 用脚本按模块剥离 RDBUS/CLKCROSSBUS/CLKCROSSDFF 实例，并将其输出拆成单根 assign <net> = 0;。
Net driven by more than one source DC 同一条连线或数组变量在多个 always 块/assign 中被驱动，综合无法推断单一驱动源。 把同一数组的所有写操作收拢到单个 always_ff 块内，或拆分为独立数组信号。
unresolved reference DC / PT 模块实例化名在当前读入的 RTL 与 link_path 工艺库中均找不到定义，DC 会将其置为黑盒。 检查 filelist.f 是否漏文件、link_path 是否漏写 * 或工艺库路径错误。

Ambiguous output redirect / Unmatched " 远端 csh 在远端默认 csh 下直接跑了 bash 风格的 2>&1、$() 或多层引号。 所有复杂命令外层套 ssh ... "bash -c '...'"，或本地写 .sh 再 scp 上去 bash 执行。
no matching host key type SSH 现代 OpenSSH 客户端默认禁用旧版服务端仅支持的 ssh-rsa 主机密钥算法。 命令加 -oHostKeyAlgorithms=+ssh-rsa -oPubkeyAcceptedKeyTypes=+ssh-rsa。
