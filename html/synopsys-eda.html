启动任何工具前：先一次配齐环境、图形与 License

远端默认 shell 是 csh，直接粘贴 export 会报错——务必先敲 bash 或在本地写成 .sh 脚本后 scp 上去执行。只要把下面这段放进工程共用初始化脚本，六大工具就能无缝互调。

实战经验：多人或后台跑 DC 时，GUI 打不开常常不是 X11 坏了，而是 License 被占满。先跑 lmstat -c 27007@lzc 看剩余席位，再决定开 design_vision 或 verdi。 
# 1) 一次性导出六大工具环境（bash）
export SNPSLMD_LICENSE_FILE=27007@lzc
export VCS_HOME=/tools/synopsys/vcs/mx2017
export NOVAS_HOME=/tools/synopsys/Verdi_O-2018.09-SP2
export PATH=/tools/synopsys/syn_vK-2015.06/bin:/tools/synopsys/pt_vK-2015.06/bin:\
/tools/synopsys/fm_vK-2015.06-SP4/bin:$VCS_HOME/bin:$NOVAS_HOME/bin:\
/tools/synopsys/sypglass/SpyGlass-L2016.06/SPYGLASS_HOME/bin:$PATH

# 2) 探活版本 + 检查 License + 验证图形通道
dc_shell -version | head -1 && vcs -ID | head -1
lmstat -c 27007@lzc
echo "DISPLAY=$DISPLAY" && xclock &

前端仿真、覆盖率与波形调试：VCS + Verdi / DVE 实战要点

仿真阶段最容易踩的坑集中在两点：一是拿错旧目录里的 simv 导致新 plusarg 完全不生效；二是忘记限制 FSDB 转储层次，跑 1,000 帧直接把磁盘写爆几十 GB。

VCS 编译、UCLI 交互与 URG 覆盖率

# 编译（含 UVM 1.2 + Verdi FSDB 接口 + DVE 调试）
vcs -full64 -sverilog -lca -timescale=1ns/1ps +v2k +lint=none \
  +incdir+./src -f uvm/filelist.f uvm/top_tb.sv case_t4.sv \
  -P $NOVAS_HOME/share/PLI/VCS/LINUX64/novas.tab \
     $NOVAS_HOME/share/PLI/VCS/LINUX64/pli.a \
  -debug_all -notice -ntb_opts uvm-1.2 -CFLAGS -DVCS \
  +define+CASE_LOOP_NUMBER=1 -top top_tb -l vcompile.log

# 覆盖率采集与多 run 合并
vcs ... -cm line+cond+fsm+tgl+branch -cm_dir simv.vdb
./simv ... -cm line+cond+fsm+tgl+branch -cm_dir simv.vdb
urg -dir simv.vdb1 -dir simv.vdb2 -dbname merged.vdb -report cov
UCLI 速查经验：想快速抓某个内部寄存器值又不想开重型 GUI，直接 ./simv -ucli，敲 stop -time 500ns → run → show -value top_tb.dut_tx.dlr_snd_inst.dlr_rqu_inst.rq_rdaddr，十秒出结果。

Verdi（FSDB）与 DVE（VPD）高效看波

# Verdi：设计层次 + 波形联动，或直接恢复信号组 .rc
verdi -dbdir simv.daidir -ssf tb.fsdb &
verdi -rc my.rc &

# DVE：本机实测必须加 -full64，否则报目录无效
dve -full64 -vpd vcdplus.vpd &
dve -full64 -cov -dir simv.vdb &

在 TB 里加转储时，务必用 $fsdbDumpvars(1, top_tb); 限制层级（或配合 $fsdbDumpon / $fsdbDumpoff 只在出错窗口开波），否则千帧回归会瞬间产生几十 GB 的 FSDB。进入 nWave 后记住五个高频键：g 选信号、Ctrl+F 搜信号、f 缩放到全局、z/Z 放大缩小、右键 Trace Driver 顺藤摸瓜追驱动源，调完立刻 File → Save Signal 存成 .rc 下次复用。

综合、时序签核、等价验证与 Lint：把每个工具用在刀刃上

后端前端交界处的四个工具分工极其明确：DC 负责把 RTL 映射到 14nm 门级网表并做主时钟收敛；PrimeTime 负责真正的静态时序签核与 **async_default** 复位恢复分析；Formality 验证网表功能与 RTL 等价；SpyGlass 提前拦截不可综合代码和静态 CDC 隐患。

DC / Design Vision（综合）

本工程先将所有 RTL 合并为单编译单元 _dlr_top_merged.sv 让宏全局可见，再 link + 读 SDC + 两阶段 compile_ultra -gate_clock。批处理用 dc_shell -64bit -f run.tcl；需要下钻看原理图与高占比子块（如 RQU 占 65.6% 面积）时开 design_vision &。

K-2015.06 三条硬限制：不导 .db（UID-530，只导 .v/.sdc/.sdf）；不报 async_default（UID-423）；set_max_fanout 不收 net（UID-119）。

PrimeTime（签核与复位恢复）

link_path 必须挂 * 加 14nm 工艺库 .db。读入综合网表前，若遇到 RDBUS/CLKCROSSBUS/CLKCROSSDFF 参数化黑盒位宽冲突，先按模块删掉这 96 个实例并在 endmodule 前逐根写标量 assign <net> = 0;（PT 不认花括号 assign {a,b}=0;）。随后用 report_timing -group {**async_default**} 即可直接看到真实的 CLKBUF 复位树链。

Formality 与 SpyGlass

Formality（fm_shell / formality &）在换库或改约束后做 RTL（-container r）与网表（-container i）的 match + verify；若网表含参数化黑盒，需先 set_black_box 或补行为模型。SpyGlass 用 spyglass -project my.prj -batch -goals lint_rtl 批量扫语法与可综合性，并可用 cdc_verify 对仿真 CDC 做静态交叉印证。

本项目四张“打开就看”高频操作卡与归档脚本

日常复核论文图表或定位回归问题时，90% 的操作都落在这四个固定入口。直接照抄命令即可，不用重新翻手册。

卡片 1 · Design Vision 看综合面积与关键路径

启动 design_vision & → File → Read Design 读入 ~/dlr_release/syn_base/_dlr_top_merged.sv 与 14nm 库 → Link Design → Read Constraints 挂 DLR_TOP.sdc → 分别执行 Report Timing (pcs_clk) 与 Report Area，双击 Hierarchy 树即可下钻原理图。

卡片 2 · PrimeTime GUI 看异步复位 recovery

启动 pt_shell -gui，在 Console 里 read_verilog /dev/shm/dlr_1123/netlist_clean3.v、link_design、source DLR_TOP.sdc、update_timing -full；菜单选 Timing → Report Timing，Group 选 async_default，Slack 阈值填 1.5，双击最差路径直接进 Schematic。

卡片 3 · Verdi 定位 NACK 同拍回退波形

TB 加 $fsdbDumpvars(1, top_tb) 后用带 -P novas.tab pli.a 的命令重编 VCS，跑 1,000 帧（p=0.01, B=32）生成 tb.fsdb，verdi -ssf tb.fsdb & 打开后拉出 dlr_rqu_inst 下的 valid_nack / rq_rdaddr / rq_wraddr 验证同拍回退。

卡片 4 · 覆盖率查看与自动收数归档

跑完覆盖率直接 urg -dir simv.vdb -report cov && dve -full64 -cov -dir simv.vdb &；本地收数统一 scp -r lzc@192.168.108.128:/dev/shm/<work>/DLR_TOP/report ./runs/$(date +%m%d)_<tag>，再用 Python 正则批量汇总所有 qor.rep 的 Critical Path Slack。
